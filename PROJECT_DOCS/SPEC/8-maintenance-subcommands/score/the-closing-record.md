#### The closing record

A `failed` run ends with `failures`. Where the item loop itself failed, it holds one `check: error` item per item the ledger records `failed`, `detail` the item as the result names it and the reason its line recorded — `<node id>: <reason>`, or `<relation> <source> → <target>: <reason>` — in the loop's order, with the `remedy` the line records where it records one and the line's `note`, where it records one, ending the `detail` before what the outcome asks of the caller ([§7](../../7-tool-result-contract-and-exit-codes/item.md)); the reason is the line's reply as a bounded, control-stripped summary, the ledger's line being the one place a reply appears whole; a run the start rebuild stopped ends with one `check: error` item naming the rebuild's own error. A `cancelled` run ends with `cancelled`, whose `item` is the loop's first item having no attempt, and `{}` where every item of the loop has one. A `refused` or `retry` run ends with its `refusals`.

**`resume`** is the call that continues the run — `score` with `--resume` — present wherever an item failed or was not reached; a `skipped` item is no such item. It comes after `counts` and `scored` and before the final record. It is absent from a dry run and from a stop before the item loop: the start rebuild's, the ledger's or the load's. It names no argument of the scope — the run's `run.yaml` records it — and includes `--state-dir`, `--config-dir` wherever the invocation named one — the resumed run must read that directory and no other, or the same run could resolve another reference — `--project-dir` wherever the invocation named one, and `--scoring-model` whenever the invocation did — the call must reach the same model, or it is a different judgement under the same run id.

**`--dry-run`** writes `run.yaml` and `items.jsonl` (one pending line per item of its set — the items it would score, manually scored ones included where `--rescore-manual` reaches them, and the stale manually scored ones it would skip), sends no request to a provider, resolves no role, and writes no KB file. Its result lists `ask`, every item the run would score, and `skip`, every stale manually scored item it would skip, each as `scored` names an item and in the loop's order, after `counts`: `total` the two together, `remaining` the items to score, `skipped` the items to skip, `done` `0`. Its `scored` is `[]`, it has no `resume` and no `roles`, and its outcome is `done`. It writes no charge record and no capture. Its run id is `dry-<id>`, and the runs kept are counted by kind ([§6](../../6-build-state-ledger-and-monitoring/index.md)), so a dry run counts only against dry runs. `--resume` with `--dry-run` is a usage refusal naming `--resume`. A dry run on an older KB is refused as a real run is (`check: index`, remedy `kbase update-format`).
