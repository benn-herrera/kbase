#### Writing the results

A value is written through the edit ops with the `manually-scored` flag `false` and the judged hash of the text its call was composed under ([§10](../../10-metadata-format-version/provenance-and-the-judged-hash.md)): a rigor answer as an entry of its node kind's op — `edit-claim`, `edit-analysis` or `edit-experiment` — with the node's `id`, a bearing answer as an `edit-edge` entry with the edge's `source`, `target` and `relation`. A value whose item's text was edited after its call was composed is written nowhere: its line is `failed`, reason "its text was edited after it was asked; the value is discarded and a resume asks it again", and a resume scores it again. A value whose node or edge is no longer in the KB is written nowhere either and fails nothing: it is skipped as [Skipped items](skipped-items.md) states. The run writes every answered value at once when its item loop ends: one mixed write batch ([§8](../write-batches/index.md)), which rebuilds the derived views as every batch does, under one hold of the KB write lock. An entry the batch refuses is that item's `failed`, and the run repeats the batch without it; a write that cannot take the lock fails every item it contained: where another writer held the lock past the wait, the item's line has the lock item's `detail`; any other lock failure records its own error. The run goes on.
