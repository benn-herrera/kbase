#### The two passes

`rigor` covers claims, analyses and experiments by id; `bearing` covers `supports`, `lifts` and `refutes` edges by relation in that order, then source, then target. A run over `all`, the default, covers the node set and then the edge set: a text edit changes a node's judged hash and the hash of every edge that touches it ([§10](../../10-metadata-format-version/provenance-and-the-judged-hash.md)), so a run scoped to one pass leaves the other stale against that edit. An all-pass run is one run: one run lock, one `run.yaml`, one `items.jsonl`, one `ledger.jsonl` and one `--resume` call, and its `run.yaml` names the set it covers (`all`); a run naming a node records `rigor`, one naming an edge `bearing`. The set is read from the KB as loaded at the run's start, once, and does not change as values are written. A work's rigor is judged with the document in hand and `edit-work` writes it; an axiom's is `1.0` by rule; a `founds` edge's bearing is the reader's, made with the work in hand, and `edit-edge` writes it. The `founds` edge has a bearing like any other — [§10](../../10-metadata-format-version/four-scoring-relations-one-arithmetic.md) gives its contribution as `bearing × the source's rigor` — and no pass reaches it.
