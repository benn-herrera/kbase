#### Refresh and format

A KB whose load fails ([§10](../../10-metadata-format-version/the-load-every-fault-refused.md)) is refused before the run's start rebuild, naming each fault. A KB in an older format is refused before it too, dry run or not, while its conversion is pending (`check: index`, remedy `kbase update-format`, [§10](../../10-metadata-format-version/one-version-read-and-written.md)); its document has `migration`. One rebuild of the derived views opens a run that makes model calls, before its items are enumerated, so the derived views are current before the item loop; a dry run writes nothing. The batch that writes the results rebuilds the derived views, so they are current whenever the run exits — finished, failed or cancelled. The start rebuild holds the KB write lock and releases it before the item loop; one that cannot take the lock ends the run there, with the lock's own outcome — `retry` where another writer held it past the wait — and the `lock` item, whose remedy is `re-run kbase score`. A crash inside the write of the results can leave the derived views stale, which `verify` reports and the next run's start rebuild repairs.
