#### One item, one call

Each call is one tool-less chat request on the `scoring` role's endpoint, over the chat protocol that endpoint's entry names ([§9.1](../../9-configuration/9.1-providers-toml-the-endpoint-pool/index.md)): `openai` speaks `chat/completions` and `anthropic` speaks the Messages protocol. Every call a run sends to an `openai` endpoint sends the run's id as its `prompt_cache_key`, so a run's calls reach one provider and share one cache entry; the Messages protocol has no such field, so a run whose endpoint speaks it sends no key. A Messages call sets the completion cap [§9.1](../../9-configuration/9.1-providers-toml-the-endpoint-pool/index.md) states; no other request is capped. The call sends the scoring role's sampling settings ([§9.2](../../9-configuration/9.2-config-toml-the-choices/index.md)) in its protocol's fields ([§9.1](../../9-configuration/9.1-providers-toml-the-endpoint-pool/index.md)), and thinking text is never part of a reply on either protocol. A call that does not complete is retried identically, up to three attempts in all, pausing 5 s before the second and 30 s before the third. What fails the item at once, on the one attempt that met it, is a provider's answer with a status that is not retryable — any non-2xx other than 429 and the 5xx class — an answer that reached the completion cap before any answer text, which an identical retry would cut off the same way, and a reply the parse refuses. `--resume` is how a user retries a failed item.
