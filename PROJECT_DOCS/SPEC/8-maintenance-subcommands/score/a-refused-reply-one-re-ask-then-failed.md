#### A refused reply: one re-ask, then failed

A `malformed` reply writes nothing, and the attempt's line records `status: failed` and the reason — the case, and where it names one the id and the lines — and **no text of the reply**. The same holds for a reply cut off at the completion cap, whose charge list may be incomplete, and for a call or a write that failed. Nothing is defaulted or supplied by kbase: a link or a node is charged, answered `none`, or left without a model call, and `*pending*` is no model's answer — the edit ops are what write one, as a person's decision.

**One corrective re-ask.** An item whose reply is `malformed` is asked once more in the same run, before the run moves past it: the same prompt, with a correction after everything the first ask sent. The correction says the question is asked again, states the refusal's case with the reply's line numbers, the cited line numbers and the id where the case names them, in text fixed with the prompt rather than the ledger's reason, quotes the reply lines the case names where it names any, and restates the answer form — the whole answer, charge lines, or `none` alone. The refused attempt keeps its own `failed` line, and the re-ask records its own line after it. A re-ask the parse refuses in turn leaves the item `failed`; no item is asked a third time in a run. A cancel that stops the re-ask in flight records no line for the item, its first attempt's included ([Outcomes](outcomes.md)). A truncated reply, a failed call and a failed write get no re-ask: a call is retried only as [One call per ask](one-call-per-ask.md) states, and a write is retried by `--resume` ([Writing the results](writing-the-results.md)).

**The guard reads the correction's inputs.** A quoted reply line that holds what the input guard refuses in an item's text ([One item, one quantity, one call](one-item-one-quantity-one-call.md)) is never sent as it stands, and nothing is stripped or escaped from it: the re-ask sends the correction without the quoted lines. The correction's other inputs are line numbers and an id read as a fault id, which hold nothing the guard refuses.

The run goes on, and `--resume` retries a `failed` item afresh.
