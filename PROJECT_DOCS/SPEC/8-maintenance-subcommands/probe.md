### `probe`

```
kbase probe [--model <provider>/<model> | --role decision|text|scoring]
            [--prompt TEXT] [--timeout DURATION]
```

One model call, no KB and no state: a diagnostic of a model selection, answered by the selection itself. A probe calls one selection, and its flags name it: `--model` names a `<provider>/<model>` reference, resolved against the pool as a role's reference is; `--role` names a role, `decision`, `text` or `scoring`, and calls the selection the configuration resolves for it — the `models.<role>` reference — supplying no model of its own; and with neither given the probe calls the `scoring` role, the selection a scoring run would make, so `kbase probe` with no arguments calls the selection a run would use. `--model` and `--role` together are a usage refusal naming the two as what may be chosen once, and a `--role` outside the three roles is a usage refusal keyed `--role`, `allowed` the three, each before anything resolves or any request is sent. An empty `--role` on the command line counts as none given; over MCP an empty `role` is a value outside the enum ([§11](../11-the-mcp-server/tools.md)). A selection that does not resolve is `refused`, naming the role's own key — `models.<role>` — or the flag, and what is missing, before any client is opened. The result states which selection answered: the role's name where `--role` or the default named it, and the reference where `--model` did.

A chat selection is one tool-less chat request, sent as a scoring run's calls are, over the chat protocol the provider's entry names ([§9.1](../9-configuration/9.1-providers-toml-the-endpoint-pool/index.md)): no tools, no history, an empty system prompt, and `--prompt` in place of the default one-word check. It sends its role's sampling settings ([§9.2](../9-configuration/9.2-config-toml-the-choices/index.md)) — the `scoring` role's where `--model` names the selection — and the result reports the effective settings, `temperature` and `thinking`. A `--role decision` selection is one decision call on the decision API its provider's `decisionApi` names, whatever the entry's `api` ([§9.1](../9-configuration/9.1-providers-toml-the-endpoint-pool/index.md)), with no system message, and its `--prompt` in place of the default predicate. `--timeout` bounds the call (default `30s`); a call that does not complete is retried as a scoring run's calls are ([One call per ask](score/one-call-per-ask.md)): backoff with jitter, `Retry-After` honoured, at most four attempts, all bounded by the call's deadline — a pause the deadline cannot cover is not waited out, and the call fails at once naming the attempts it made. The result reports what a ledger cannot — the selection, the provider, the model, the time to the first token, the call's wall time, the finish reason, the reply, and the usage the provider reported — and its outcome follows the call: `done` where it completed, or where a chat answer was cut off at the completion cap before any answer text (`finish-reason` `length`, `reply` empty); `failed` otherwise, with the attempt's own outcome and the provider's words in the failure, and its `remedy` where the provider refused the call's key ([§9](../9-configuration/index.md)). It reads no KB and reads or writes no state directory: it prints its result and exits.

`probe` is also a read-only MCP tool taking the same arguments ([§11](../11-the-mcp-server/tools.md)). Each call is a paid model call, and its MCP note is stated in [§11](../11-the-mcp-server/served-text.md).

Result keys: [§7](../7-tool-result-contract-and-exit-codes/index.md).
