### `probe`

```
kbase probe [--model <provider>/<model>] [--decision | --text | --scoring]
            [--prompt TEXT] [--timeout DURATION]
```

One model call, no KB and no state: a diagnostic of a model selection, answered by the selection itself. A probe calls one selection, and its flags name it: `--model` names a `<provider>/<model>` reference, resolved against the pool as a role's reference is; `--decision`, `--text` and `--scoring` each call the selection the configuration resolves for that role — the `models.<role>` reference — and supply no model of their own; and with none of the four given the probe calls the `scoring` role, the selection a scoring run would make, so `kbase probe` with no arguments calls the selection a run would use. The four are mutually exclusive: more than one is a usage refusal naming all four as what may be chosen once, before anything resolves or any request is sent. A selection that does not resolve is `refused`, naming the role's own key — `models.<role>` — or the flag, and what is missing, before any client is opened. The document states which selection answered: the role's name where a role flag or the default named it, and the reference where `--model` did.

A chat selection is one tool-less chat request, sent as a scoring run's calls are, over the chat protocol the provider's entry names ([§9.1](../9-configuration/9.1-providers-toml-the-endpoint-pool/index.md)): no tools, no history, an empty system prompt, and `--prompt` in place of the default one-word check. It sends its role's sampling settings ([§9.2](../9-configuration/9.2-config-toml-the-choices/index.md)) — the `scoring` role's where `--model` names the selection — and the document reports the effective settings, `temperature` and `thinking`. A `--decision` selection is one decision call on the decision API its provider's `decisionApi` names, whatever the entry's `api` ([§9.1](../9-configuration/9.1-providers-toml-the-endpoint-pool/index.md)), with no system message, and its `--prompt` in place of the default predicate. `--timeout` bounds the call (default `30s`); a call that does not complete is retried at once, up to the same three attempts as a scoring run's calls ([One item, one call](score/one-item-one-call.md)), so the deadline is spent on attempts rather than on pauses. The document reports what a ledger cannot — the selection, the provider, the model, the time to the first token, the call's wall time, the finish reason, the reply, and the usage the provider reported — and its outcome follows the call: `done` where it completed, or where a chat answer was cut off at the completion cap before any answer text (`finish-reason` `length`, `reply` empty); `failed` otherwise, with the attempt's own outcome and the provider's words in the failure, and its `remedy` where the provider refused the call's key ([§9](../9-configuration/index.md)). It reads no KB and reads or writes no state directory: it prints its document and exits.

`probe` is also a read-only MCP tool taking the same arguments ([§11](../11-the-mcp-server/tools.md)). Each call is a paid model call, and its MCP note is stated in [§11](../11-the-mcp-server/served-text.md).
