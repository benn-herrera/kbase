### 9.4 Key-file permission warning

When a `providers.toml` entry sets `apiKeyFile`, the store contains no key under its name, and the host is not Windows, kbase checks the resolved key file's permission bits. If they grant group-read or other-read, it reports a warning (as a fault, [Provider commands](provider-commands.md)) naming the key file by its path and as the one `providers.toml` names, never by the field that states it, with the offending mode and recommending `chmod 600`. The entry stays usable. A key file that cannot be read ([§9.1](9.1-providers-toml-the-endpoint-pool/index.md)) is named the same way, with the refused-key remedy ([A refused key](a-refused-key.md)). This is the only file-permission behaviour kbase applies to a file it did not create.
