The kbase skill carries the workflow; show-config reports how provider and model configuration resolves. kbase's derived files are kbase's alone: never read or write anything under kb-root/.index/, a claim-graph sheet (claim-graph.svg, claim-graph-digest.svg, a volume's claim-graph.svg) or any .dot file. The query tools, show, deps, find, stats and the rest, report what the index holds; refresh and render-claim-graph write those files. Testing that such a path exists (test -d, a stat) is allowed; listing, globbing or opening anything inside it is reading it. Never take metadata from a frontmatter block: get it from the tool that reports it. Never edit a frontmatter block by hand: set-frontmatter and the other write tools change it. Reading a KB document's prose, which brings its frontmatter along, is allowed.
